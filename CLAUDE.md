# Paragon PR7-K: notes for Claude

This repository starts as a copy of **Paragon PR7-E** (the utility processor, repo `ARYEZ/Paragon-PR7-E`) at PR7-E **0.15.0**, full history included, to become **Paragon PR7-K**, the **synthesizer** of the PR7 family: a VST3 instrument, inspired by VPS Avenger (which the owner has, but finds too heavy on CPU). Its siblings: **PR7-G** (guitar, repo `ARYEZ/Paragon-PR7-G`), **PR7-B** (bass, `ARYEZ/Paragon-PR7-B`), **PR7-V** (vocal, `ARYEZ/Paragon-PR7-V`), **PR7-C** (`ARYEZ/Paragon-PR7-C`) and **PR7-E** (utility). Everything below describes how the project is built, tested and released, and how the owner likes to work.

## First: make it its own plugin (done in 0.1.0)

All of this was done in 0.1.0; it's kept as the record of what makes PR7-K its own plugin.

1. **CMakeLists.txt** (`juce_add_plugin`): `PRODUCT_NAME` "Paragon PR7-K", `BUNDLE_ID` `com.paragon.paragonpr7k`, `PLUGIN_CODE` `Pr7k` (never PR7-G's `Px1a`, PR7-B's `Pr7b`, PR7-V's `Pr7v`, PR7-C's `Pr7c` or PR7-E's `Pr7e`), `PLUGIN_MANUFACTURER_CODE Prgn`; an instrument (`IS_SYNTH TRUE`, `NEEDS_MIDI_INPUT TRUE`, `VST3_CATEGORIES Instrument Synth`, no input bus); version restarted at 0.1.0 (the CMake target name stays `ParagonX1`).

4. **Logo** (`source/ui/Logo.cpp`): "-K", built from the P's parts in the same slanted, speed-cut lettering (one outline: the path fills even-odd).
5. **Text:** About (SETTINGS), README, the preset browser (says presets, not rigs).
6. **Release workflow:** `Paragon PR7-K.vst3`, `ParagonPR7-K-${TAG}-...` zips, "Paragon PR7-K ${TAG}".
7. **CHANGELOG.md** starts at 0.1.0.
8. **Releases re-enabled** in the 0.1.0 commit.

## The plan: a synth inspired by VPS Avenger, built in stages

The owner supplied Avenger's manual (2.3.1, in the owner's private repo `ARYEZ/manuals`: never commit it here, it's Vengeance's). The owner uses all of it (supersaw leads, pads, basses, wavetables, arpeggiator, drum sequencer, effects), so nothing is dropped: the CPU savings must come from structure, not from leaving things out. From the manual, Avenger's load is the product of up to 8 oscillator tabs x (notes + chorder voices) x V-Saw voices, plus long release tails that "still use CPU", oversampled FM and up to 48 effects. Ours: voices that have faded below audibility end, unison/chorder copies are computed together, oscillators read band-limited tables (no oversampling needed), switched-off parts cost nothing. CPU is a test like any other.

Owner's choices: a **synth panel in the PR7 look** (not the floor-unit face); PR7-E's **EQ, COMP, DOMINION and LIMITER DSP are kept** for the effects rack (stage 7), their stomp pages go; **Windows VST3**.

Stages (each a released plugin):
1. **Core synth: done in 0.1.0.** `source/dsp/synth/`: `WaveTables.*` (band-limited saw, triangle, sine at 28 levels a third of an octave apart, up to 512 harmonics, 4096 samples, straight interpolation; harmonics allowed up to `sampleRate - 20 kHz` so anything that folds lands above 20 kHz; pulse = saw minus a saw shifted by WIDTH), `Envelope.h` (AHDSR, curves `bend()`: k = curve x 10, negative fast first; `step(n)` for the filter envelope once per 16 samples), `Filter.h` (TPT state-variable filter; 24 dB = resonant SVF + Butterworth SVF, 18 = SVF + one-pole, 6 = one-pole without resonance; DRIVE = tanh with first-order antiderivative anti-aliasing, in double), `Noise.h`, `SynthSettings.h` (everything in real units; the processor fills it each block), `Engine.*` (voices = notes, each running up to 8 oscillators; pool of 64 + 16 for stolen notes fading over 3 ms; per-oscillator VOICES limit fades the oldest note's copy over 5 ms; mono with a held-note stack; glide constant-time; slow things every 16 samples). Parameters (version hint 1): `osc{n}{On,Wave,Volume,Pan,Transpose,Fine,Random,PhaseRand,Phase,Gain,Width,FadeIn,Invert,Noise,NoiseColour,NoiseWidth,Sub,SubWave,SubOct,SubInvert,Filter,Voices}` for n = 1 to 8, `flt1*` and `amp1*` (numbered: Avenger has four of each; `osc{n}Filter` is a bool now and can become a choice of filters later, its 0/1 reading the same), `playMode legato glide glideMode bendUp bendDown voices`, `patchLevel`; global `outputGain` (default -6 dB) `bypass` `tune`. Never reorder `oscWaveNames`, `subWaveNames`, `subOctaveNames`, `noiseWidthNames`, `playModeNames`, `glideModeNames`, `filterTypeNames`. UI: `ui/SynthPanels.*` (OSCILLATORS with tabs re-pointing one set of `ParamControl`s, FILTER, two envelopes, AMP, PLAY), `ui/SynthDisplays.*` (wave, filter response from the analog prototypes, envelope shape), `ui/SynthControls.*`; an on-screen `MidiKeyboardComponent` (C1-B7). Factory presets: starting points in bank A (`rigs/FactoryRigs.cpp`: 8 in 0.1.0, 3 more in 0.2.0). Tests: `tests/SynthTests.cpp` (pitch, aliasing vs a plain ramp, pulse harmonics, sub, noise colour, envelope timing and curves, filter response vs its display for every type, slopes, resonance, keytrack, velocity, drive aliasing vs plain tanh, voice stealing, mono modes, legato and glide, oscillator voice limit, sustain pedal, pitch wheel, CPU: 8 notes x 4 saws with a driven filter under 25% of a core, about 3.5% here).
2. **Unison, vibrato and chorder: done in 0.2.0** (Avenger's V-Saw and Chorder). Per oscillator, version hint 2: `osc{n}{UniVoices,UniMix,UniDetune,UniSpread,UniOctaves,VibMode,VibWave,VibRate,VibAmount,VibFade,VibCurve}` and `osc{n}Ch{k}{On,Coarse,Fine,Pan,Vol}` for k = 1 to 4 (appended to `ParamIDs::oscSettings`; the processor finds each by `ParamIDs::oscSetting ("name")`, worked out at compile time). Engine: up to 35 copies per oscillator per note (`Copy`, numbered note x 7 + unison copy; copy 0 of the key uses the oscillator's own phase, with the sub and noise); `Engine::unisonPosition` (for 7: +-1/3, +-2/3, +-1), detune = DETUNE squared x 100 cents (our choice), OCTAVES stacks extra copy u at ((u - 1) mod (octaves + 1)) octaves; extra copies start at random phases; vibrato per interval (global: one phase per oscillator; independent: per copy, speed x 0.85-1.15). MIX 0 is bit-exact with stage 1 (tested). `addCopy` works out all positions first, then reads (lets the compiler vectorise); `tables::levelFor` searches a precomputed count list (it ran 28 exp2s per call: half the cost of 672 copies). Never reorder `vibratoModeNames`, `vibratoWaveNames`. UI: the oscillator panel's WAVE / VOICES pages (`OscillatorPanel::Page`), `VoicesDisplay` (copies by pan and pitch). Presets A09-A11. CPU in the tests: supersaw chord (56 copies) about 2.6%, 672 copies about 17% (limits 25% and 60%).
3. **Wavetables, shape bending, sync, FM/AM, FFT and freeform editing, the shaper**: built and released in parts, as PR7-E's EQ was (each a release):
   - **3a, wavetables: done in 0.3.0.** `dsp/synth/Wavetable.*`: `WavetableSource` (name, frame size 32-4096, frames as floats: what presets and projects save) and `Wavetable::build` (each frame's harmonics by FFT, or a direct DFT for frame sizes that aren't powers of two; DC removed; scaled so the loudest frame peaks at 1; then every frame at the basic waves' 28 levels, each level a power of two of at least 2048 samples: at 8 per harmonic, bright frames' interpolation images aliased to -47 dB; 2048 brings them under -90). About 250 KB a frame (16 MB for 64 frames, 64 MB for 256), so tables are built on the message thread when chosen, never on the audio thread. `locate` maps INDEX and FRAMES (frames spread evenly) to two frames and a blend (SMOOTH) or the nearest (STEPPY); the engine glides the blend across each 16-sample interval. `factoryTables` (10 of our own, generated: never reorder `names`), `wavetableFiles` (WAV/AIFF/FLAC: frame size from a "clm " chunk, else a whole file of 4096 samples or fewer as one frame, else 2048s; over 256 frames, 256 spread evenly; saved as 16-bit, gzipped, base64). Parameters (version hint 3): `osc{n}{Table,WtIndex,WtMode,WtFrames}`; `OscWave::wavetable` appended (never reorder `oscWaveNames`, `wavetableModeNames`). Loaded tables aren't parameters: `Rig::wavetables` (by oscillator) and a `Wavetables` child in the project state (taken out before `replaceState`); undo snapshots compare them by pointer. The processor owns the tables (`loadedTables`, `playingTables`), hands the audio thread raw pointers (`tablesForAudio`) and keeps replaced ones 2 s (`retiredTables`) so a block still playing one can't read freed memory; `updateWavetables` runs from the timer (so automation switching WAVE to WAVETABLE gets its table within a tick), `prepareToPlay`, `applyRig` and `setStateInformation`. UI: `WavetableChooser` (TABLE: factory list, the loaded table, "Load WAV file..."; a file dropped on the oscillator panel loads too), INDEX / MODE / FRAMES in place of WIDTH's row-3 space, `WaveDisplay::paintWavetable` (frames stacked front to back, INDEX's bright). Presets A12-A14. Tests: `tests/WavetableTests.cpp` (frames and levels by harmonic, no aliasing on a bright frame high up, SMOOTH/STEPPY/FRAMES by level, gliding INDEX without clicks, every factory table, WAV cutting, saving, the processor keeping a loaded table through project, preset and undo, CPU). The WT travel envelope / sequencer is a modulator: stage 4.
   - **3b, SHAPE: done in 0.4.0.** `dsp/synth/WaveBend.h` (our own design): SKEW (Avenger's "XCITE side": not that name on the plugin) and PINCH ("XCITE mid") are phase warps smooth round the cycle (SKEW `u + a (1 - cos 2 pi u) / 2 pi`, PINCH `u + b sin (2 pi u) / 2 pi`, two passes each, a = 0.95 skew, b = 0.9 pinch), kept per oscillator in a 1024-point `WarpTable` remade only when they change (it was four cosines per sample per copy). FORMANT: the wave played k times faster (k = 2^(-3f) left, 2^(-2f) right), a gap after it when k > 1; modes CUT, FADE, X-FADE, X-FADE 2 (our reading of the manual; never reorder `formantModeNames`, `crushModeNames`). CRUSH: RATE (3 to 256 steps a cycle, never finer than 2 samples) and BIT (mid-rise rounding, 1 to 128 levels each side, first-order ADAA). Anti-aliasing: the level is chosen for `hz x speed` (FORMANT's k times the warp's fastest, times 1.6 headroom when FORMANT or a warp is on: without it, FORMANT's bursts folded side tones back to -25 dB); FORMANT's edges get polyBLEP + polyBLAMP (slopes measured a hair either side), RATE's steps polyBLEP. A cut saw stays the hard case (its own reset sits on FORMANT's edge). std::floor / round avoided per sample (library calls on x86-64 without SSE4.1 and on MSVC): most of the CPU cost. Parameters (version hint 4): `osc{n}{Skew,Pinch,Formant,FormantMode,Crush,CrushMode}`. UI: the oscillator's SHAPE page (`OscillatorPanel::Page::shape`: the WAVE page's left column, BEND / FORMANT / CRUSH, `ShapeDisplay` with plain and bent waves); `WaveDisplay` draws the bent wave on every page. Presets A15-A17. Tests: `tests/ShapeTests.cpp` (what each does to a sine, each mode's edges, the curves smooth and monotonic, aliasing vs the plain way at A5 with limits and E7 reported, copies and wavetables, CPU per control).
   - **3c, SYNC / FM / AM: done in 0.5.0.** `dsp/synth/OscModulation.h` (ratios and grids, shapes, SYNC's envelope, WIN's raised cosine) and `Engine.cpp`'s `Modulation` + `renderBent` (one per-sample path for SHAPE and these). SYNC: the copy at `2^(5 x amount)` (amount + ENV x envelope, its ratio ramped across each 16-sample interval), restarted at each cycle start; that edge goes through WaveBend's BLEP/BLAMP (`syncEdge`), the WIN modes multiply by a raised cosine instead. FM: phase modulation, depth `2 x amount^2` cycles; from a shape (its own phase per copy, `modPhase`, at RATE x the copy's pitch; LOCK starts it at the wave's phase x ratio) or another oscillator (rendered first into `fmSignals`, not mixed in: `isModulator`; an oscillator can't modulate itself); the edge smoothing uses how far the read really moved (`lastX`). AM: `1 - a + a x modulator`. The level is chosen for `hz x bend speed x modulation speed` (SYNC's ratio, FM's `1 + depth x ratio x the shape's steepest slope`, AM's `1 + ratio`, plus SHAPE's 1.6 headroom for SYNC and FM). Avenger's four FM modes (continuous, oversampled, table, table windowed) are one here; its table modes aren't built (offered if FM sounds harsh up high). Never reorder `syncModeNames`, `modShapeNames`, `fmSourceNames`, `modGridNames`. Parameters (version hint 5): `osc{n}{SyncAmount,SyncMode,SyncEnv,SyncEnvTime,SyncEnvCurve,FmAmount,FmSource,AmAmount,AmShape,ModRate,ModGrid,ModLock}`. UI: the FM page (`Page::fm`), `ShapeDisplay` draws SHAPE + SYNC (no envelope) + FM from a shape + AM, and the ratio. Presets A18-A20. Tests: `tests/ModulationTests.cpp` (against formulas: SYNC's octave and harmonics, ADD, WIN, the envelope; FM sample for sample from a shape and an oscillator; AM's sum and difference; grids; LOCK; aliasing vs the plain way; CPU).
   - **3d, the FFT editor: done in 0.6.0** (0.5.0 never published: a random-dependent test failed on Windows; `Engine::seedRandom`, set by the tests' `Player`, makes them repeatable). `dsp/synth/Spectrum.h`: `SpectrumEdit` (256 bands of dB, -48 = gone to +24; saved as text "band:dB"; kept per oscillator by the processor, in `Rig::spectra` and a `Spectra` child of the project, compared in undo snapshots), `spectrum::gainDbFor` (SWEEP: harmonic h gets what's drawn at h / 2^(4 sweep); FLIP: dB negated), `pulsePattern` (VSTRENGTH: sin (2.4 h)), `basicWave` (a basic wave as a one-frame source, 4096 samples, built with `normalise` false so its level matches the plain table). `Wavetable::build (source, gain, normalise)` applies a per-harmonic gain. The processor's `SpectralBuilder` thread builds the edited copy (and VSTRENGTH's second copy: gains x (1 + s pattern) and (1 - s pattern)) when the key (curve, sweep, flip, strength, wave, pulse width, a wavetable's samples) changes; latest request per oscillator wins; results installed from the timer (`installSpectralResults`), handed to the audio thread as `OscSettings::spectral` / `spectralPulse`, retired 2 s; `finishTableBuilds()` for tests. The engine plays `spectral` through the wavetable path (a wavetable's INDEX on its frames), swings to the partner at VSPEED (`OscState::pulsePhase`), and does LP / HP live by blending the table's levels (`blendFor`: cutoff position 3 log2 (512 / harmonic), SLOPE widens the blend from 1 to 6 levels; HP subtracts the blend at its cutoff), which needs the general per-sample path. Parameters (version hint 6): `osc{n}{FftSweep,FftFlip,FftLp,FftHp,FftSlope,FftVSpeed,FftVStrength}`. UI: the FFT page (`Page::fft`, `ui/SpectrumEditor.*`: FREE / HARMONIC (24 harmonics by interval, then the rest: our layout) / BIN, SHIFT for lines, RANDOM, RESET); `WaveDisplay::editedFor` shows the edited copy. Presets A21-A22. Tests: `tests/FftTests.cpp`.
   - **3d, part 2, FREEFORM and the resampler: done in 0.7.0.** `dsp/synth/Freeform.h`: `FreeformDrawing` (512 points, -1 to 1; SMOOTH A / B = three box-blur passes up to an eighth of the cycle wide, A before SPLIT and B after, blended over 32 samples; EDGE over up to a quarter cycle each end: ADAPT moves both ends to their middle, ZERO fades them, SYMMETRY blends with the mirror image; NORMALIZE; rendered to 2048 samples and built as a one-frame table; saved as text: 6 settings then 512 values). `OscWave::freeform` appended (no new parameters: the drawing isn't automatable, like the FFT curve). The processor keeps `drawings` / `freeformTables` per oscillator (`setDrawing` builds on the message thread: about a millisecond), in `Rig::drawings` (only non-flat ones), a `Drawings` child of the project and undo snapshots; the FFT editor edits a drawing as any wave. Never reorder `freeformEdgeNames`. UI: the DRAW page (`Page::draw`, `ui/FreeformEditor.*`: drawn line thin, played cycle bright; drawing switches WAVE to FREEFORM; START FROM, SMOOTH A/B, SPLIT, NORMALIZE, EDGE, EDGE MODE, WAV export). Resampler: `wavetableFiles::CutOptions` (frame size, root note via `cycleLength`, every nth, spread N, start / end) and `cut`; a file over 4096 samples asks how to cut it (`loadWavetableAsking` in `SynthPanels.cpp`). Preset A23 (Drawn Growl). Tests: `tests/FreeformTests.cpp`.
   - **3e, the SHAPER: done in 0.8.0** (stage 3 complete). `dsp/synth/Shaper.h`: 10 models of our own (the manual doesn't list Avenger's; never reorder `shaperModelNames`, `shaperPlaceNames`), each a curve and its antiderivative (first-order ADAA, in double; a channel restarts when its model changes), run at 2x (`Channel::distort`: a 47-tap Kaiser half-band each way, 12 odd taps, flat to 18 kHz, -80 dB on what would fold below 18 kHz; `latency` 23 samples; MIX's dry is delayed to match, `delayedDry`); ADAA at 2x rolls the top off by cos (pi f / 96 kHz). DRIVE 0-1 = 0 to +36 dB, `makeUp` so a full-scale sine peaks near 1; DC blocker (5 Hz) after the lopsided models; two Simper bells before (`Bell`, worked out once per block in `Engine::process`), EQ SPLIT band 1 left, band 2 right; MIX and OUTPUT are ours. Engine: each note's oscillators are grouped by route (`Path`, key bit 0 the filter, bits 1-4 the shapers), each path with its own filter and shapers (`assignPaths`, `processPath`, `processShaper`); with no shapers the paths are the old filtered / dry pair, output bit-identical to 0.7.0 (checked against a build of 0.7.0). Parameters (version hint 7): `shp{k}{On,Model,Drive,DriveVel,Eq1Gain,Eq1Freq,Eq1Q,Eq2Gain,Eq2Freq,Eq2Q,EqSplit,Place,Mix,Output}` for k = 1 to 4 (`ParamIDs::shaperSettings`), `osc{n}Shp1-4` (appended to `oscSettings`, on by default). UI: the FILTER panel's tabs FILTER / SHP 1-4 (`FilterPanel::showPage`; one set of shaper controls re-pointed), `ShaperDisplay` (curve and EQ). Presets A24-A25. Tests: `tests/ShaperTests.cpp`. Not built: Avenger's noise-bypass option for the filter and shaper.
4. **Modulation**, built and released in parts:
   - **4a, the mod matrix, LFOs, macros and controllers: done in 0.9.0.** `dsp/synth/Modulation.h` (`mod::Source`, saved by `sourceIds`: never rename, only append; `Field`/`Target` and `mod::apply` in Engine.cpp; `Route` with base 0-1, amount, +/% `combine`, `bend` = |s|^(4^curve), lag; `LfoSettings`/`LfoState`: waves, sync straight/triplet/dotted by `lfoDivisionBeats`, triggers VOICE/GLOBAL/FIRST NOTE/LAST NOTE, OFFSET fitted in as (wave + o) / (1 + |o|), delay, fade-in, one-shot; never reorder `lfoWaveNames`, `lfoSyncNames`, `lfoDivisionNames`, `lfoTriggerNames`). Destinations: `ModDestinations` (knobs the engine follows live; not SKEW/PINCH, FFT SWEEP/FLIP/VSTRENGTH, shaper EQ, choices). Parameters (version hint 8): `lfo{n}{Wave,Rate,Sync,Division,Trigger,Phase,Offset,Delay,FadeIn,OneShot}` for n = 1 to 4, `macro1-3`, `macroButton1-2`. Parameters (version hint 9): `menv{n}{Mode,Trigger,Sync,Speed,Steps,Flip,Offset}` for n = 1 to 8. UI: the MOD page's `ModulatorPanel` (tabs LFO / ENV / SHAPE; LfoDisplay or `ui/MultiPointEditor.*`; START FROM shapes), macros and matrix below. Presets A29-A30. Tests: `tests/EnvelopeModTests.cpp`. Not yet: the drawn shapes driving vibrato and FM.
   - **4c, the PITCH module: done in 0.11.0.** `PitchSettings` in SynthSettings.h (envelope on, `mod::EnvelopeSettings` for mode/speed/steps/flip, range, keytrack, bend lag, glide curve, glide split) and `OscSettings::pitchEnvelope` (follows it).    - **Part 1, analyse and rebuild: done in 0.44.0** (the owner's ask and name: a "preset cloner" like those made for other synths). `dsp/synth/Mimic.*` (our own design, by measurement): `analyse` (one note; attack to 90%, then held (a plateau of 0.25 s, falling under 6 dB/s, above -30 dB: sustain the median of its latter half, decay as the time to 10% of the way / 0.23 for a curve of -1, release from the slope after it) or dying (sustain 0, decay from the slope over the 87 dB a curve of -1 covers; release the same); the tone: up to 64 frames 40 ms apart from the start to where it settles (held) or to -30 dB (dying), each 2-6 cycles cut at the local pitch, resampled to 2048 (Catmull-Rom), turned so the fundamental starts at 0, levels the cycles' power at the averaged phase, harmonics only below the cycle's Nyquist, every frame at one RMS (the loudness is the AMP's); vibrato (the pitch less its 300 ms average, smoothed over 50 ms, autocorrelation 2.5-10 Hz above 0.3, depth sqrt 2 x the deviation, delay where it first reaches half); a swoop (from the first clear reading until within 35 cents for 60 ms, at least 60 cents off, under 600 ms); unison (each cycle's harmonics 2-10 as shares of the cycle: beating spread over 0.12 that speeds up with the harmonic, the high ones' crossing rate over 1.8x the low ones' (noise shakes them evenly); detune from the crossing rate per harmonic: 5 copies 8 / 20 cents read 8 / 23); noise (an 8192 FFT of the steady part: what's more than 12% of a harmonic away, less 0.2% of the harmonics for leakage, kept over 3%; colour from its centre); width (side / mid). `analyseFile`, `noteName` (C4 = 60). `rigs/MimicRig.*`: `makeRig (analysis, Choices)` (a clean sound: oscillator 1 the wavetable at FINE = the cents, TRAVEL one-shot FREE at 1 / the frames' time; Snapshot: `PARAGON_SNAPSHOT_PAGE=mimic` (a made G3 with vibrato and breath).
   - **Part 2, the MATCH and REFINE: done in 0.45.0**. `Mimic.h`: `Analysis::audio` (the recording, mono), `Fingerprint` (32 log bands 60 Hz-16 kHz and the level, every 10 ms, 40 ms Hann windows) and `compare` (`Score`: `gainDb` the level difference weighted by the recording's loudness; LOUDNESS the mean |dB| apart per 10 ms, each floored 60 dB under the recording's loudest; TONE where the recording is within 30 dB of its loudest, each moment's bands as a shape (less its top band, floored at -40), the mean |dB| apart; MATCH = 100 x e^(-mean of the two / 10); `levels` the candidate's, gain-matched, for the picture). `source/MimicRefiner.*`: a private `ParagonX1AudioProcessor` (`renderer`, 48 kHz, 512) plays a candidate (`play`: `applyMimic`, `prepareToPlay` from silence, `finishTableBuilds`, `seedRandomForTest (1)`; the root note at 0.8, off at `releaseStart - start`, up to `maxSeconds` 6 s, left and right mixed); `score` (sets the rig's `patchLevel` by `gainDb`); `begin` / `step` (coordinate search: knobs only for what was estimated and chosen: AMP attack x, decay x, sustain + (held sounds), release x, decay / release curves + (scale 3), noise oscillator VOLUME x, UNI DETUNE +, VIB AMOUNT x, TR RATE x; up then down, kept if MATCH rises over 0.05; three passes, factor 1.6 then its square roots, amount 0.12 then halves; about 30-50 plays). ## The project

- An AGPLv3 **JUCE VST3** instrument, a synthesizer in the PR7 family's look, sharing the family's code.
- **Code layout:** the synth in `source/dsp/synth/`, PR7-E's effects (for stage 7) in `source/dsp/effects/`, `dsp/eq/`, `dsp/dominion/`; UI in `source/ui/`, parameters in `source/Parameters.*`, presets ("rigs" in the code, as across the family) in `source/rigs/`, tests in `tests/`.
- **Parameters:**
  - Saved by ID and choices by **index**: only ever *append* choices, never reorder.
  - New parameters get a new version hint number.
  - Migrations for changed defaults live in `setStateInformation` and `Rig::fromXml`.
- **Shared DSP pieces:** `BypassFade` and `TailWatch` (EffectUtils.h), and `Circuit` (Circuit.h: models analog stages from their schematics, part by part).

## Build, test, check

- **Build:** `cmake -B build && cmake --build build -j8`. On a fresh Linux machine, install the packages listed in `.github/workflows/build.yml` first.
- **Tests (Catch2):** `xvfb-run -a build/tests/ParagonX1Tests`. All must pass. Windows gives a thread 1 MB of stack (Linux 8 MB): keep big data (patterns, tables) on the heap, never inline in `ModMatrix`, `Rig`, `Settings` or the engine (`tests/StackSizeTests.cpp`); before a release run the tests once under `ulimit -s 1024` to catch what Linux hides. New features get tests that check what the feature really does to the sound (levels, frequencies, harmonics), not just that it runs. The synth's test harness (`Player` in `tests/SynthTestUtils.h`) uses `synth::Settings`' defaults, so those must match the parameters' defaults, and seeds the engine's random choices (`seedRandom (1)`), so a test hears the same on every run and computer.
- **pluginval:** `xvfb-run -a <pluginval> --strictness-level 10 --validate-in-process "build/ParagonX1_artefacts/Release/VST3/Paragon PR7-K.vst3"`. Check its exit code. CI runs it too.

## Releases

- Bump `project(ParagonX1 VERSION x.y.z)` in CMakeLists.txt and add a matching `## x.y.z` section at the top of CHANGELOG.md, then push.
- CI builds Windows, macOS and Linux and publishes a GitHub Release with the three zips, using that changelog section as the notes. It publishes from a push to **any** branch whose version isn't released yet.
- Run the full tests (under `ulimit -s 1024`) **after** the version bump, on exactly what will be pushed: 0.63.0's first build failed CI on the fuzz test when a run made just before the bump had passed.
- After pushing, check the release published (all three zips) about 15 minutes later, **and that its `target_commitish` is your commit**. If the version was already taken, CI skips silently and the release you'd link is someone else's build.
- **One chat per plugin at a time.** In October 2026 two chats released PR7-G and PR7-V under the same version numbers: one chat's releases were skipped, and features (and a UI fix) went missing from the builds the owner installed. Before choosing a version, check the repo's tags *and* other branches for unreleased work; if another branch is ahead, merge it first so every release contains everything.
- The owner installs from GitHub Releases on **Windows**.
